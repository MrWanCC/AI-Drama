# 连载日更与单章写作工作流

本文件补充 `fiction-write/SKILL.md` 的执行细节。它把“写一章”限制在用户明确指定的范围内，避免重启会话后自动连写或跳过章纲。

## 1. 路由与停靠点

- 只说“写作/继续”而没有章号或数量时：先报告项目阶段、最后完成章、下一章细纲状态，停在选择菜单，不自动写正文。
- 用户指定“写第 N 章”时：只写第 N 章；没有明确要求时，默认一次一章。
- 用户明确说“日更/连续写”时：每轮最多写 3 章；每章仍独立执行写前检查和写后落盘，批次结束后停止。
- “开书”默认只完成构思锁定、首批细纲和底本初始化；除非同一句明确要求“并写第 1 章”，不得顺手写正文。
- 同时命中多个意图时，优先级为：修改 > 指定章 > 日更 > 开书 > 状态诊断。

## 2. 写前闸门

按顺序确认：

1. 能找到 `.novel/state.json`，且 `progress.writing_started` 为 `true`。
2. 能定位本章细纲：优先读取 `大纲/第{卷号}卷/详细大纲.md` 中的本章段落；若项目已经采用逐章文件，也可读取对应 `大纲/细纲_第{章号}章.md`。
3. 细纲至少有核心事件、目标情绪、人物/视角、结尾推动力。缺字段不要替模型杜撰，先返回 `outline_underfilled` 和补纲清单。
4. 目标文件不存在，或用户明确允许覆盖时，才落盘正文。覆盖前保留原稿副本或可恢复的版本记录。

缺少细纲时不得用“凭感觉续写”绕过闸门。旧项目字段不全可以兼容，但必须把缺失字段报告出来，补齐后再写。

## 3. 上下文按需加载

本轮实际读取并记录来源，不用聊天记忆代替文件事实：

| 优先级 | 文件 | 目的 |
|---|---|---|
| 必读 | 本章细纲 | 事件、情绪、禁区、字数与结尾推动力 |
| 必读 | 上一章正文或摘要 | 衔接动作、时间、未闭合问题 |
| 必读 | `追踪/上下文.md`、`追踪/伏笔.md`、`追踪/时间线.md` | 当前状态、伏笔、时间约束 |
| 按需 | `追踪/角色状态.md`、相关设定卡 | 只加载本章出场或被改变的实体 |
| 按需 | `.novel/project_memory.json` | 作者已经确认过的写法偏好 |
| 按需 | `拆文库/` 或题材参考 | 只借鉴结构与技法，不复制角色、事件和原句 |

只保留“如果不知道就会写错”的内容。不得把整本设定、整套参考库一次性塞入写作上下文。

## 4. 题材与文风召回

- 先读项目的 `设定集/文风档案.md`；其中有实质约束时，它优先于参考书文风。
- 再按题材从 `references/genre-writing-formulas.md`、`style-genre-modules.md` 或对应专题文件中选取少量规则。
- 题材参考只约束读者期待、爽点/情绪、节奏密度和场景颗粒，不覆盖本章目标、人物动机和项目文风。
- 没有实时榜单或拆文证据时，不能把经验判断写成“当前市场事实”。

## 5. 章纲预算与正文边界

细纲中的情节点按功能和预算组织，而不是先堆事件数量：

- 密点（冲突、反转、爽点、关系峰值）展开写；
- 铺垫和关系过渡写清因果，但不靠重复心理和环境注水；
- 疏点（赶路、转场、重复信息）快速带过；
- 预算合计 `Σ` 目标落在 `[目标字数, 目标字数 × 1.1]`。不够时先补细纲节点，超出时先压缩疏点；不要写完再靠空话补字。

正文只能扩写本章细纲计划内的情节点。需要提前释放后续卷的真相、底牌、关系结论或终局矛盾时，先暂停并报告越界风险。

## 6. 写后收尾

依次执行：

1. 运行 `scripts/check_prose.py --check 正文/第{章号}章-*.md`，修复 blocking findings；advisory findings 记录但不机械替换。
2. 完成独立审查时，保存原始 JSON、报告和指标；审查器缺失、失败或结果不完整时明确写 `unverified`，不得报告“已通过”。
3. 只把正文中已经发生的事实写回 `追踪/上下文.md`、`追踪/伏笔.md`、`追踪/时间线.md` 和 `追踪/角色状态.md`；大纲是计划，不覆盖正文事实。
4. 运行 `chapter-commit` 记录章节、正文路径和内容哈希；提交记录不是审查通过证明。
5. 当前批次完成后停靠，报告已生成文件、验证结果和下一步选项。

章尾优先落在具体动作、物件、台词或即时危险上。不要用“他终于明白了”“更大的风暴即将来临”等总结/预告替代下一章的推动力。

## 7. 失败恢复

- `outline_underfilled`：只补纲，不写正文。
- 正文检查失败：只修复当前章并重新检查，不自动扩大到后续章节。
- 写回失败：保留正文，报告未同步的文件，单独补写回。
- 批量中断：保存已完成章和断点，下次从未完成章开始，不重写已完成章。
