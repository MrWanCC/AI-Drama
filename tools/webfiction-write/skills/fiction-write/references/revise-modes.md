# 章节修改模式详细流程

> 本文件是 fiction-write/SKILL.md "章节修改模式（内建）" 的详细展开。
> 主 SKILL.md 只保留模式速查表和自动检测推荐，具体流程在用户进入修改模式时加载本文件。

## Re-craft 模式（大改，核心设计）

```
Step 1: 分析变更
  系统对比新旧版本，提取"变更事实清单"
  ┌─ 变更事实清单 ──────────────┐
  │ 1. [人名] 配角 "张三" → "李四"  │
  │ 2. [关系] 主角与张三"敌对"→"盟友"│
  │ 3. [情节] 第 7 章结尾改变         │
  │ 4. [伏笔] "张三是卧底" → 删除     │
  └────────────────────────────┘

Step 2: 执行修改
  → 修改目标章节正文

Step 3: 影响范围探测（核心步骤）
  系统扫描后续已写章节，检测是否存在引用变更项：
  ┌─ 影响范围报告 ──────────────────┐
  │ 🔴 第 8 章：引用了被改情节 → 需修改 │
  │ 🟡 第 9 章：提到旧名 1 次 → 换名   │
  │ 🟢 第 10 章：无关                   │
  │ 🔴 设定集/角色卡/张三.md：需改名    │
  │ 🔴 追踪/伏笔.md：一条伏笔需删除     │
  └────────────────────────────────┘

  → 只读每章摘要做快速过滤，命中再读正文确认
  → 扫描范围控制在 10 章以内

Step 4: 用户确认影响范围（展示报告，默认全部选中）

Step 5: 用户确认后执行变更传播
  只处理用户确认的章节；未确认项只保留报告，不静默修改：
  → 修改受影响的后续章节（人名替换/情节调整）
  → 更新设定集相关文件
  → 更新追踪系统（伏笔/时间线/角色状态）
  → 更新大纲相关条目
  → 在报告中标记被修改的章节为 "revised"

Step 6: 全量校验
  → 对受影响章节批量跑轻量 reviewer（只查连续性问题）
  → 一致性检查
  → 伏笔闭环检查
```

## Rewrite 模式（重写）

```
Step 1: 确认范围
  → 全章重写还是多章重写？
  → 章纲是否需要先调整？

Step 2: 可选的细纲修改
  → 如果情节走向变了，先编辑章纲 → 用户确认

Step 3: 执行重写
  → 进入本 skill 的 Deep 模式完整流程
  → context-agent（LLM 扮演）重新整理上下文
  → 起草正文

Step 4: 变更传播
  → 同 Re-craft Step 3-6
  → 范围更广（可能波及拉取后续所有章节）

Step 5: 底本刷新
  → data-agent（LLM 扮演）重新提取本章事实
  → 将 artifact 写入 .novel/tmp/，再运行 chapter-commit --data-artifacts
  → 运行 projections retry --chapter {章号} 刷新脚本负责的摘要投影
  → index/memory/vector 等宿主专属投影由宿主按实际能力处理，并记录 skipped/未验证状态

Step 6: 回填大纲
  → 将最终正文的结构化节点写回章纲
```

## 修改模式的写回规则

修改完成后只写回用户确认范围内、且由正文事实支持的文件。传播引擎可以给出候选范围，但不能替用户批准级联修改。

必备确认：
- 修改前保留原稿副本或版本记录
- 展示后续章节、设定集和追踪文件的影响清单
- 跨章/跨卷传播前询问是否继续
- 文件在上次 commit 后有用户手动编辑时，先问是否保留

## 撤销 / 回滚

- 修改前复制原稿或创建用户可识别的版本记录；本仓库脚本不会自动打 git tag。
- 如果项目本身使用 Git，可由用户自行创建提交或 tag，再进行修改。
- 恢复后重新跑确定性检查和必要的 reviewer；不要声称底本已自动刷新。
- 版本记录是补丁级安全网，不是完整分支管理。

## 修改模式参考

变更传播引擎依赖每章的摘要文件（.story-system/summaries/ch{章号}.md）做快速过滤。
运行 `projections retry --chapter {章号}` 后，仓库脚本会从正文重建摘要；如果摘要缺失，退化为逐章读正文判断（慢但可用）。
写回规则与正文写作一致（只写确认的事实，跨章/跨卷先确认）。
轻量 reviewer 同 fiction-review 的 reviewer schema，但只检查连续性问题维度。
章节回滚的安全网由 git tag 提供，不依赖专用脚本。
